# 2.14 - Reports MVP

## Overview
Reports MVP adds institutional reports with scoped JSON views and export (PDF/Excel).

- Backend module: `backend/src/modules/reports`
- Frontend feature: `frontend/src/features/reports`
- Page: `frontend/src/pages/ReportsPage.tsx`
- Router prefix: `/reports`

## ERD Changes

```text
organizations (1) ---- (N) report_runs
centers       (1) ---- (N) report_runs (optional)
circles       (1) ---- (N) report_runs (optional)
users         (1) ---- (N) report_runs [requestedBy]
report_files  (1) ---- (N) report_runs [outputFileId]

organizations (1) ---- (N) report_files
centers       (1) ---- (N) report_files (optional)
circles       (1) ---- (N) report_files (optional)
users         (1) ---- (N) report_files [createdBy]
```

### Added Enums
- `ReportType`: `ATTENDANCE | FOLLOW_UP | EXAMS | FINANCE`
- `ReportRunStatus`: `PENDING | COMPLETED | FAILED`
- `ReportFileKind`: `PDF | XLSX`

### Added Tables
1. `report_files`
- metadata for exported files: name, mime, size, storage key, creator, expiration.

2. `report_runs`
- audit trail for each report generation: requester, filters, status, summary, output file link.

## RBAC Matrix

| Role | Attendance | Follow-up | Exams | Finance | Export |
|---|---|---|---|---|---|
| SUPER_ADMIN | Yes (All) | Yes (All) | Yes (All) | Yes (All) | Yes |
| CENTER_ADMIN | Yes (Scoped center) | Yes (Scoped center) | Yes (Scoped center) | Yes (Scoped center) | Yes |
| SUPERVISOR | Yes (Scoped) | Yes (Scoped) | Yes (Scoped) | Yes (Scoped) | Yes |
| TEACHER | Yes (Own circles) | Yes (Own circles) | Yes (Own circles) | No (403) | Yes for allowed report types |
| PARENT | Yes (Own children) | No (403) | Yes (Own children) | Yes (Own children) | Yes for allowed report types |

## Scoping Rules
- Scoping is enforced server-side via `authGuard + attachScope`.
- Requested `centerId/circleId` are validated against scope.
- Parent data is scoped using `scope.studentIds`.
- Teacher finance access is blocked in domain with `403`.

## Endpoints

- `GET /reports/catalog`
- `GET /reports/attendance?from&to&centerId?&circleId?`
- `GET /reports/follow-up?from&to&centerId?&circleId?&actorRole?`
- `GET /reports/exams?from&to&centerId?&circleId?&examStatus?`
- `GET /reports/finance?from&to&centerId?&status?`
- `POST /reports/export`
- `GET /reports/exports/:id/download`

## Sample cURL

### Login
```bash
curl -X POST http://localhost:4000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"superadmin@rafiq.local","password":"Rafiq@1234"}'
```

### Attendance report JSON
```bash
curl "http://localhost:4000/reports/attendance?from=2026-01-01&to=2026-02-20" \
  -H "Authorization: Bearer <ACCESS_TOKEN>"
```

### Export exams report as Excel
```bash
curl -X POST http://localhost:4000/reports/export \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "reportType":"EXAMS",
    "format":"XLSX",
    "filters":{"from":"2026-01-01","to":"2026-02-20"}
  }'
```

### Download exported file
```bash
curl "http://localhost:4000/reports/exports/12/download" \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  --output report.xlsx
```

## Export Lifecycle
1. Request arrives at `POST /reports/export`.
2. `report_runs` row is created with `PENDING`.
3. Data is generated by report type (attendance/follow-up/exams/finance).
4. File is rendered (`pdfkit` / `exceljs`) and stored in `storage/reports`.
5. `report_files` metadata is inserted.
6. `report_runs` is updated to `COMPLETED` (or `FAILED` with error message).

## Seed Logic
- Seed creates baseline report files and 3 report runs (2 completed + 1 failed simulation).
- Running seed again yields same final counts in DB (no duplicates remain after reset step).
- Verified counts after two consecutive runs:
  - `report_runs = 3`
  - `report_files = 2`
