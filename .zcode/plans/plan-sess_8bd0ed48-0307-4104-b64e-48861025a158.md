# Engineering Audit Plan — Rafiq Al-Quran v2 (Repair vs Rebuild)

## Stage 1 Discovery — COMPLETED (evidence-based findings)

**Backend** (Express 5.2 + TS 5.9 + Prisma 6.15 + PostgreSQL):
- Schema: 3,568 lines, **98 models, 96 enums**, 266 indexes, 144 cascades, **no soft deletes**, `User` model has **104 relations**
- Migrations: 22 active + 52 archived (squashed baseline 2026-05-23); history **consistent**; an active cleanup program exists (DB-CLEAN 1a/1d done, phase 4 pending with 7 `@deprecated` markers)
- 27 modules, 258 files, ~70k LOC; **21/27 follow** controller/service/repository/routes/validation layering; exceptions: finance-v2 (33 files, no repo layer), staff-operations (no repo layer), certificates, geo, media, system
- ~357 API endpoints; centralized middleware chain (auth → rbac → scope → validate) with centralized org/center/circle scope resolution + 5-min cache
- Auth: JWT access (15m) + refresh (7d) stored in DB, bcryptjs, zod-validated env (secrets ≥32 chars)
- **Dual finance stack**: finance-v2 (vouchers/movements) + accounting (double-entry ledger) + legacy Invoice/Payment with **live dual-write flag** `FINANCE_V2_DUAL_WRITE_LEGACY_PAYMENT=true`
- 3-way tuition overlap: TuitionPlan / StudentTuitionAssignment (deprecated) / StudentFeeProfile; legacy surah-parsing bridges in follow-ups; orphaned `MatnProgressStatus` enum
- RBAC middleware contains hard-coded "fallback roles" regex route lists (defensive patches)
- God services: accounting.service 2,303 / staff-operations.service 2,287 / exams.service 2,216 / golden-records 1,913 lines
- Tests: 23 backend files (65% finance-scoped), 5 frontend, 8 mobile; CI exists (.github/workflows/ci.yml)
- Security hygiene: **DB password hardcoded in backend package.json scripts** ("Rafiq@2026!"); .env files properly gitignored

**Frontend**: React 19 + Vite 7 + react-query 5 + zustand + axios singleton with refresh-token handling; 17 features, 272 files; largest pages: GoldenRecords 1,440 / Dashboard 1,419 / FinanceAssets 1,226 lines

**Mobile**: Flutter Clean Architecture (core/domain/data/presentation), Riverpod 2 + GoRouter + dio + freezed + hive/sqflite; 251 dart files, role-scoped presentation dirs; largest screens ~1,600 lines

## Preliminary direction (to be confirmed by Stages 2–9, not yet the final decision)
The foundation appears **capable of carrying the system**: committed layering, centralized security/scoping, consistent migration history with an active cleanup program, modern stacks across all three apps. The critical risks (god services, dual finance stack, 104-relation User, near-zero test coverage outside finance) are all incremental-refactor targets, not rebuild justifiers. **Initial direction: REPAIR & REFACTOR, not REBUILD** — final decision with confidence % will be issued only after full evidence collection.
